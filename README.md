# ספריית בית ספר הלל - מערכת ניהול השאלות

המערכת פוצלה לשני חלקים נפרדים:

- **backend/** - שרת Node.js (JavaScript) שמחזיק את כל הדברים הרגישים: בדיקת שם משתמש/סיסמה,
  הגדרות ה-Firebase, וההרשאות (מי מנהל, מי ספרן רגיל). שום סיסמה, מפתח, או הגדרת Firebase כבר
  לא נמצאים בקוד שרץ בדפדפן.
- **frontend/** - עמוד HTML/CSS/JS סטטי שמדבר עם השרת דרך `/api/...` בלבד.

## הרצה מהירה

```bash
cd backend
cp .env.example .env      # ואז לערוך את .env ולמלא JWT_SECRET אמיתי (ראו הוראות בתוך הקובץ)
node server.js
```

ואז פותחים בדפדפן: `http://localhost:4000`

**אין צורך ב-`npm install`** - הקוד כתוב עם ה-JavaScript המובנה של Node.js בלבד (ללא ספריות
חיצוניות), כדי שההרצה תהיה פשוטה ואמינה גם במחשב בית ספר רגיל. יש קובץ `package.json` לצרכי
תיעוד/עתיד בלבד.

בדיקות (רצות אוטומטית, כולל הרצה מלאה של השרת מול נתונים זמניים):

```bash
cd backend
node --test
```

## מה השתנה

### 1. האימות (כניסה למערכת) עבר לחלוטין לשרת
לפני כן, שם המשתמש והסיסמה ("chop" לכולם, ו-"Mark2013" עבור מארק) היו כתובים בגלוי בתוך קוד
ה-JavaScript שרץ בדפדפן של כל אחד - כל תלמיד שהיה פותח "כלים למפתחים" יכול היה לראות אותם.

עכשיו:
- הסיסמאות נשמרות בשרת בלבד, בקובץ `backend/src/data/credentials.json`, **מוצפנות/מגובבות**
  (hash) עם המנגנון המובנה של Node (`crypto.scrypt`) - לא בטקסט גלוי.
- הדפדפן שולח שם משתמש+סיסמה לשרת (`POST /api/auth/login`), השרת בודק ומחזיר "עוגיית" התחברות
  מאובטחת (`HttpOnly`, כך שקוד JavaScript בדפדפן לא יכול לקרוא אותה).
- תהליך שני השלבים של מארק (סיסמה רגילה + סיסמת מנהל-על) נשמר בדיוק כפי שהיה, רק שהשלב השני
  נבדק גם הוא בשרת (`POST /api/auth/verify-super`).
- **חדש:** לכל איש צוות יש עכשיו כפתור "אפס סיסמה" (מפתח 🔑) בפאנל הניהול, כדי שאפשר יהיה
  להחליף את סיסמת ברירת המחדל המשותפת לסיסמה אישית. כל משתמש יכול גם לשנות את הסיסמה שלו
  בעצמו דרך התפריט האישי ("שינוי סיסמה").

### 1.5 סיסמאות עכשיו שורדות "פריסה מחדש" (redeploy) בשירותים כמו Render
בגרסה הקודמת הסיסמאות (המוצפנות/hash) נשמרו רק בקובץ מקומי על השרת. זה עבד מצוין
במחשב רגיל, אבל בשירותי אחסון חינמיים כמו Render **הדיסק המקומי לא נשמר בין פריסות** -
כל פעם שמעלים קוד מחדש (או שהשרת נרדם ומתעורר בתוכנית מסוימת), הקובץ המקומי נמחק
וכל הסיסמאות האישיות שהוגדרו חוזרות לברירת המחדל ("chop" / "Mark2013").

עכשיו: כשה-Firebase מוגדר (יש `FIREBASE_API_KEY` ו-`FIREBASE_PROJECT_ID` בקובץ `.env`),
הסיסמאות (עדיין מוצפנות עם `scrypt`, לעולם לא בטקסט גלוי) נשמרות גם ב-Firestore, באוסף
נפרד `library_credentials` - בדיוק כמו הצוות וההשאלות, כך שהן שורדות פריסה מחדש. הקובץ
המקומי עדיין קיים כ"גיבוי" אוטומטי למקרה שה-Firestore לא זמין לרגע.

### 2. הגדרות ה-Firebase עברו לשרת
`firebaseConfig` (ה-`apiKey` וכו') כבר לא מופיע בקוד שרץ בדפדפן - הוא נמצא רק בקובץ `backend/.env`
שנשאר על השרת. השרת מתחבר ל-Firestore באותו פרויקט (`hillellibrary-59912`) ואותה מבנה נתונים
בדיוק כמו קודם, כך שההתחברות לענן ממשיכה לעבוד על אותם נתונים חיים.

אם ה-Firestore לא זמין (או שלא הוגדר), השרת עובר אוטומטית ל"מצב מקומי" - שמירה בקובץ
`backend/src/data/local-db.json` - בדיוק כמו שהאפליקציה הישנה נהגה לעשות בדפדפן, רק שעכשיו זה
קורה בשרת.

### 3. אפשרות להוסיף הערה לכל השאלת ספר
לכל רשומת השאלה יש עכשיו שדה "הערה" - עמודה חדשה בטבלה עם סמל 📝. לחיצה עליה פותחת חלון קטן
להוספה/עריכה של הערה חופשית (עד 500 תווים), לדוגמה "הספר חזר עם דף קרוע" או "התלמיד ביקש הארכה".

### 4. הנתונים הקיימים נשמרו
הקובץ ששלחת (`index_6.html`) היה למעשה תמונת מצב אמיתית של האפליקציה החיה (הכפתור הישן
"הורדת קובץ קוד המערכת" שמר את כל הדף כפי שהוא נראה באותו רגע, כולל הנתונים). חילצתי ממנו את
כל הצוות וההשאלות הפעילות ושמרתי אותם ב-`backend/src/data/seed.json`:

- **צוות:** מארק (מנהל-על), הלל (מנהל), לאון (מנהל), יאשה (ספרן רגיל) - עם אותם מזהים (IDs)
  שהיו ב-Firestore, כדי שהחיבור לענן ימשיך לזהות אותם נכון.
- **5 השאלות פעילות:** אדם אהרון בזן, אלמוג לוי, רוני ברמן, אדם אהרוני, דילן מילונציק - עם כל
  הפרטים (כיתה, ספר, תאריכים) כפי שהופיעו בקובץ.

נתונים אלו משמשים כ"גיבוי" שנטען אוטומטית בפעם הראשונה שהשרת רץ, ומשמשים גם כרשת ביטחון אם
הענן לא זמין. אם ה-Firestore כבר מכיל את הנתונים העדכניים האמיתיים (שכן זו ההנחה - זה פרויקט
פעיל), השרת פשוט ימשיך לעבוד איתם ברגע שיתחבר.

## החלטות שקיבלתי בעצמי (Auto Mode) - כדאי לבדוק

מכיוון שהמערכת פעלה במצב שמנחה אותי להתקדם עם הנחות סבירות במקום לעצור ולשאול, הנה הדברים
שהחלטתי, ולמה - אם משהו לא מתאים, קל לשנות:

1. **סיסמת ברירת מחדל למשתמשים קיימים/חדשים נשארה "chop"** (ניתן לשינוי ב-`.env` דרך
   `DEFAULT_STAFF_PASSWORD`), וסיסמת מארک השנייה נשארה "Mark2013" (`SUPER_ADMIN_SECRET_PASSWORD`).
   כך המערכת ממשיכה לעבוד בדיוק כמו קודם ביום הראשון, אבל **מומלץ מאוד** שכל אחד יחליף את
   הסיסמה שלו לסיסמה אישית דרך הכפתור החדש ברגע שנוח.
2. **שיטת החיבור ל-Firestore:** במקום דרישה למפתח שירות (service account) של Firebase, השרת
   מתחבר בדיוק כמו שהדפדפן הישן עשה - "כניסה אנונימית" (anonymous sign-in) עם אותו `apiKey`.
   זה מספיק כי חוקי האבטחה (Security Rules) של הפרויקט כבר מאפשרים את זה היום. יתרון: לא היה
   צורך לבקש ממך מפתח נוסף. חיסרון: אם בעתיד תרצה להגביל את הגישה ל-Firestore כך שרק השרת
   שלך יוכל לגשת אליו (ולא כל דפדפן), יהיה צורך לעבור למפתח שירות אמיתי - אשמח לעזור בזה כשתרצה.
3. **הסרתי את כפתור "הורדת קובץ קוד המערכת"** מפאנל הניהול - הוא היה שומר את ה-HTML החי כפי
   שהוא נראה, אבל בארכיטקטורה החדשה הקוד כבר מאורגן בתיקיות backend/frontend רגילות שאפשר
   לגבות/לשתף ישירות, כך שהכפתור הפך למיותר.
4. **ללא npm install:** בחרתי לכתוב את כל השרת עם היכולות המובנות של Node.js (ללא Express,
   bcrypt וכו') כדי שההרצה תהיה הכי פשוטה שאפשר במחשב בית ספר - `node server.js` ותו לא.
5. **איפה להריץ את זה בפועל:** לא הגדרתי אחסון ענן (hosting) - זה שרת Node.js רגיל שאפשר
   להריץ על כל שירות שתומך ב-Node (Render, Railway, VPS, מחשב בבית הספר וכו'). ב-Netlify
   (שם רץ הקוד הישן) אי אפשר להריץ שרת עם מצב (state) כזה ישירות - יידרש שירות אחר או
   Netlify Functions בהתאמה. אם תרצה עזרה בפריסה (deployment) בפועל, ספר לי איפה תרצה
   שזה ירוץ ואני אכוון את ההוראות לפי זה.

## הרשאות (ללא שינוי בהתנהגות, רק נאכף עכשיו בצד השרת)

- **מנהל-על (מארק):** היחיד שיכול להעניק/להסיר הרשאת "מנהל", היחיד שיכול להסיר מנהל אחר,
  ואי אפשר להסיר אותו או לשנות את התפקיד שלו.
- **מנהל (admin):** יכול להוסיף/להסיר ספרנים רגילים, לפתוח את פאנל הניהול.
- **ספרן רגיל (librarian):** יכול לרשום/לעדכן/למחוק השאלות ולהוסיף הערות, אך לא לגשת לפאנל הניהול.

## המשחקים ("משחק" בתפריט האישי)

בתפריט האישי יש כפתור **משחק**. הוא פותח מסך בחירה עם שלושה משחקים (עם תמונה, תיאור והשיא האישי
של כל אחד), ואפשר לחזור למסך הבחירה בכפתור "כל המשחקים":

- **ריצה בעיר** - משחק ריצה תלת-ממדי בשלושה מסלולים: מתחמקים ממשאיות ורכבות (חלקן נוסעות לכיוונך),
  קופצים מעל מחסומים ואוספים מטבעות. אפשר לאסוף **נעלי קפיצה** (קופצים מעל משאיות ועולים לרוץ על גגות
  רכבות), **מגנט** ו-**x2 מטבעות**. כלי רכב שנוסעים אליך מוצבים כך שתמיד נשאר נתיב פנוי שאפשר להגיע אליו.
- **קפיצה בשמיים** - משחק "קפוץ מעל דברים" בסגנון משחק הדינוזאור של כרום, בתלת-ממד: רצים על איים
  מרחפים, קופצים מעל לבנים ובורות, לחיצה ארוכה = קפיצה גבוהה יותר, חץ למטה = נחיתה מהירה. יש **קפיצים**
  שמעיפים לשמיים, קופסאות "?" עם מטבעות, **תהומות**
  שעוברים על אבני קפיצה (האדומות נופלות!), **שבילים עיליים** מלאי מטבעות, ועולם שמתחלף מיום לשקיעה ללילה.
  אפשר לאסוף **רקטה** (עפים מעל הכול בנהר של מטבעות), **קפיצה כפולה**, **מגן** (מציל פעם אחת), **מגנט** ו-**x2**.
- **קרב באי** - משחק יריות בתלת-ממד נגד 19 בוטים (בלי מולטיפלייר). לוחצים "צנח!" וצונחים מהשמיים,
  פותחים גליידר ונוחתים איפה שרוצים על אי גדול עם 7 אזורים (עיר, כפר, מבצר, יער, מחסנים, מגדלור וחווה).
  האי גדול (רדיוס 360 מטר) ויש בו 11 אזורים: עיר, שכונת גנים, כפר, מבצר, מחסנים ונמל, מגדלור, חווה, הר עם
  מגדל רדיו, אגם עם בקתות, מחנה צופים ויער, ועוד בתים בודדים בשטח. אפשר להיכנס לבתים, ויש שלל בפנים.
  פותחים **תיבות** ומוצאים **נשקים** (אקדח, תת-מקלע, רובה סער, רובה ציד ושלושה רובי צלפים עם כוונת: רגיל, חצי-אוטומטי וכבד) ב-5 רמות
  נדירות (אפור, ירוק, כחול, סגול, זהב), תחמושת, תחבושות, ערכות עזרה ראשונה ושיקויי מגן. **הסערה**
  מתכווצת בשלבים ומכריחה את כולם להתקרב. כל מטבע במפה שווה 3, מקבלים **50 מטבעות על כל חיסול**,
  **300 על ניצחון**, בונוס על מקום גבוה (עד 150) ומטבע על כל 5 שניות שרידות. הבוטים נוחתים, אוספים נשקים, מתרפאים, בורחים מהסערה, זזים לצדדים ונסוגים כשהם
  פצועים, ומכוונים כמו שחקנים (עם זמן תגובה ופספוסים), ונלחמים גם זה בזה. מקשים: WASD, עכבר לכיוון, לחיצה שמאלית
  לירי, ימנית לכוונת, רווח לקפיצה ובאוויר לפתיחה/סגירה של הגליידר (קרוב לקרקע הוא נפתח לבד), E לפתיחה ולאיסוף,
  R לטעינה, 1-5 להחלפה, Q לזריקת החפץ שביד, M למפה. תחבושות, ערכות עזרה ושיקויי מגן נכנסים לתיק כמו נשקים:
  בוחרים אותם ולוחצים ירי, וזה לוקח כ-3 שניות.
  יש גם כפתורי מגע לטלפון. במחשב חלש המשחק מוריד אוטומטית את איכות הגרפיקה כדי להישאר חלק.
- **ריצה בעיר ו"קפיצה בשמיים"**: עם **x2** כל מטבע באמת הופך לשני מטבעות שמסתובבים יחד, ואוספים את שניהם.

בכל המשחקים יש כפתור "מסך מלא", והשיא נשמר בדפדפן.

### קרב באי עם חברים (עד 4, כל אחד במחשב שלו)

- כשנכנסים ל"קרב באי" מגיעים ל**לובי**: הדמות שלך עומדת על משטח זוהר, ולידה עוד 3 משטחים ריקים עם "+".
- **הזמנה**: כותבים בצד את שם המשתמש של החבר/ה (השם שאיתו נכנסים לאתר) ולוחצים "הזמנה". אצל החבר/ה
  קופצת הודעה בצד - גם כשהוא/היא סתם באתר וגם כשהמשחק פתוח - עם "הצטרפות" / "לא עכשיו". הצטרפות פותחת
  את המשחק ישר בלובי של הקבוצה, ושם רואים את הדמויות של כולם (עם הסקינים שלהם), את השמות ומי מוכן.
- כשכולם לוחצים **"מוכן!"** כולם צונחים יחד מאותה נקודה. הבוטים, השלל והסערה זהים אצל כולם; אין פגיעה בחברים
  לקבוצה; רואים את החברים עם השם שלהם מעל הראש, בצד (בריאות ומגן) ובמפה. מי שהודח צופה בחבר/ה שנשאר/ה,
  ו**כשכל הבוטים מחוסלים - כל הקבוצה מנצחת** (גם מי שהודח מקבל את בונוס הניצחון).
- ככל שהקבוצה גדולה יותר יש יותר בוטים: לבד 19, בזוג 23, בשלישייה 27 וברביעייה 31.
- איך זה עובד: באתר יש ערוץ "חי" (WebSocket בכתובת `/api/live`, בלי ספריות חיצוניות) שמחזיק את הקבוצות,
  ההזמנות וה"מוכן", ומעביר הודעות בין השחקנים במהלך הקרב. המחשב של מוביל/ת הקבוצה (👑) מריץ את הבוטים, הסערה
  והשלל ושולח אותם לשאר; כל אחד מריץ את הדמות שלו. אם המוביל/ה סוגר/ת את המשחק באמצע, הקרב נגמר לכולם.
  המטבעות עדיין נשמרים לכל אחד דרך אותה בדיקת זמן בשרת (אי אפשר לרמות דרך הערוץ החי).
- הקוד: `backend/src/realtime/` (השרת), `frontend/games/arena/js/net.js`, `lobby.js` ו-`main.js` (המשחק),
  וההודעה באתר ב-`frontend/js/app.js`. בדיקות: `backend/test/live.test.js`.

### מטבעות, חנות וסקינים

- המטבעות שאוספים במשחקים **נשמרים בחשבון של כל משתמש** בשרת (ב-Firestore באוסף `library_game_profiles`,
  ובקובץ המקומי כשאין חיבור לענן).
- בחלון המשחקים יש כפתור **חנות**: שלושה סקינים שעובדים בכל המשחקים - זהב (1,000), ניאון (2,500) וגלקסיה
  (5,000); ככל שיש יותר אפקטים, הסקין יקר יותר. אפשר ללבוש סקין, להסיר אותו ולהחליף בין סקינים שקניתם.
- **הרשאת מנהל ב-50,000 מטבעות**: ספרן שקונה אותה הופך למנהל (אדמין) אמיתי במערכת. מארק יכול להסיר את
  ההרשאה כרגיל מפאנל ניהול הצוות.
- **הגנה מרמאות**: השרת לא סומך על הדפדפן. הוא מודד בעצמו את הזמן שעבר מתחילת כל ריצה ועד סופה, ומקבל
  לכל היותר 8 מטבעות לשנייה (שחקן מצוין אוסף 3-5); ריצה שנשארה פתוחה יותר מ-30 דקות נספרת כ-30 דקות.
  כל ריצה נספרת פעם אחת בלבד, והמחירים והיתרה נשמרים רק בשרת.

המשחקים בנויים מחלקים בקוד פתוח, עם רישיונות שמתירים שימוש חוזר:
- מנגנון "ריצה בעיר": [Boxy Run](https://github.com/wanfungchui/boxy-run) של Wan Fung Chui (Apache 2.0, בגרסה מותאמת)
- מנגנון "קפיצה בשמיים": [T-Rex Runner](https://github.com/wayou/t-rex-runner), משחק הדינוזאור של Chromium (BSD, בגרסה מותאמת)
- מודלים, טקסטורות וצלילים: [Kenney](https://kenney.nl) (CC0 - נחלת הכלל)
- מנוע תלת-ממד: [three.js](https://threejs.org) (MIT)

כל משחק נמצא בתיקייה משלו תחת `frontend/games/`, כולל הרישיונות ו-`NOTICE.md` עם פירוט השינויים.
המשחקים רצים בתוך iframe נפרד, כך שהם לא נוגעים בנתוני הספרייה ולא בשרת. משחק נטען רק כשבוחרים
אותו, ונעצר לגמרי כשחוזרים למסך הבחירה או סוגרים את החלון.

## ניהול כיתות

מנהלים (אדמין) ומארק (סופר אדמין) יכולים, דרך הכפתור "ניהול צוות (אדמין)", להוסיף, לשנות שם ולהסיר כיתות.

- הרשימה נשמרת בשרת: ב-Firestore באוסף `library_classes` (כשהחיבור לענן פעיל), ובקובץ המקומי כשלא. בפעם הראשונה היא נטענת מ-`classes.json`.
- שינוי שם כיתה מעדכן גם את כל ההשאלות הקיימות שלה. הסרת כיתה לא מוחקת השאלות. אי אפשר להסיר את הכיתה האחרונה.
- ההרשאה נבדקת בשרת (`/api/classes`), לא רק בדפדפן. ספרן רגיל יכול לקרוא את הרשימה אך לא לשנות אותה.
- אם Firestore Security Rules אצלכם מתירות רק אוספים מסוימים, יש לוודא שגם `library_classes` מותר (בדרך כלל הכלל מכסה `artifacts/{appId}/public/data/{collection}`).
